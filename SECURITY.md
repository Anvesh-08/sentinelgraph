# SentinelGraph — Security, Privacy & Ownership Policy (`SECURITY.md`)

---

## 1. Ownership & Licensing Guarantee
SentinelGraph is an original, independently architected software product licensed under the **Apache License 2.0**.
- Zero code, schemas, or datasets are copied from proprietary employer systems, financial institutions, or commercial AML vendors.
- All customer profiles, account numbers, tax ID hashes, sanctions entries, and transaction histories generated by the seeding engine are **100% synthetic** and deterministically generated via mathematical models.

---

## 2. Authentication & Cryptographic Standards
1. **Password Storage:** User passwords are never stored or logged in plaintext. All passwords use `hashlib.pbkdf2_hmac('sha256', password, salt, 210000)` with a unique 128-bit cryptographic salt per user and constant-time comparison (`hmac.compare_digest`).
2. **Session Tokens:** API authentication uses signed stateless tokens formatted as `base64url(header).base64url(payload).base64url(HMAC_SHA256_signature)` with strict expiration (`exp`) and role claims.
3. **Role-Based Access Control (RBAC):** Every API route enforces granular role checks (`L1_ANALYST`, `L2_INVESTIGATOR`, `QA_COMPLIANCE_OFFICER`, `RISK_ENGINEER`, `SYSTEM_ADMIN`).
4. **Four-Eyes Separation of Duties:** The case state machine programmatically prevents the user who investigated or escalated a case (`investigator_id`) from approving the case in QA (`qa_reviewer_id`).

---

## 3. Data Protection & SQL Injection Prevention
1. **Parameterized Queries Only:** Every database query in the repository layer uses parameterized bindings (`?` placeholders). Dynamic string interpolation of user input into SQL statements is strictly prohibited.
2. **PII Hashing:** Sensitive identifiers such as Tax IDs (SSN/EIN) are stored as salted/normalized SHA-256 digests (`tax_id_hash`) to enable privacy-preserving entity resolution without exposing raw government identifiers.
3. **Tamper-Evident Audit Ledger:** Every state change appends a record to `audit_logs` where:
   $$H_n = \\text{HMAC-SHA256}(K_{\\text{audit}}, H_{n-1} \\parallel t_n \\parallel u_n \\parallel a_n \\parallel e_n \\parallel p_n)$$
   Any unauthorized modification or deletion of historical rows invalidates the chain and is immediately flagged by `/api/v1/audit/verify`.

---

## 4. Pre-Commit Secret Hygiene Checklist
Before any commit or push:
- Verify `.env` and `*.db` files are ignored by `.gitignore`.
- Run `python3 -m backend.app.cli.main audit-security` to scan the repository tree for accidental high-entropy secrets, private keys, or credentials.
